## 3. Findings ledger
- **HR-1 — High — confirmed static.** The operator/control surface is intentionally unauthenticated and should not be treated as a public multi-user control plane. The README states, “**The local `/api/operator/overlay-link` endpoint itself has no operator authentication**” and warns “**do not use a shared/public preview**” with real Twitch secrets ([`README.md:65-68`](https://github.com/knarayanareddy/habitat-relay/blob/07f29808c43930d779029dc64e4beb7b471b85e1/README.md#L65-L68)). The server exposes `GET /api/operator/overlay-link`, `GET /api/events`, and `GET /api/operator/status` with no auth gate in the sampled code ([`src/server.js:130-153`](https://github.com/knarayanareddy/habitat-relay/blob/07f29808c43930d779029dc64e4beb7b471b85e1/src/server.js#L130-L153)). Impact: if this app is hosted for anything beyond trusted single-operator use, any party reaching the origin can inspect operator state and mint a fresh read-only overlay capability. Recommended correction: add authenticated operator sessions before any shared/public deployment; until then, keep this scoped to trusted local or tightly access-controlled preview use.

- **HR-2 — Medium — confirmed static.** Host/proxy trust is header-derived and needs an explicit deployment contract. The CSRF gate uses “**const allowedHost = forwarded || req.headers.host**” ([`src/server.js:43-50`](https://github.com/knarayanareddy/habitat-relay/blob/07f29808c43930d779029dc64e4beb7b471b85e1/src/server.js#L43-L50)). Overlay URLs are built from “**const host = forwardedHost || req.headers.host**” and “**const protocol = forwardedProto**” ([`src/server.js:130-138`](https://github.com/knarayanareddy/habitat-relay/blob/07f29808c43930d779029dc64e4beb7b471b85e1/src/server.js#L130-L138)). OAuth cookie security also keys off `x-forwarded-proto` ([`src/server.js:205-210`](https://github.com/knarayanareddy/habitat-relay/blob/07f29808c43930d779029dc64e4beb7b471b85e1/src/server.js#L205-L210)). Impact: if the proxy does not scrub/set forwarded headers exactly as assumed, CSRF decisions, cookie `Secure` behavior, and generated overlay URLs can drift from the real public origin. Recommended correction: pin a trusted public base URL, trust forwarded headers only from an approved proxy tier, and add negative tests for forged header combinations.

- **HR-3 — Medium — owner decision / confirmed documented limitation.** Privacy-conscious dedupe exists, but retention and recovery policy are not operationally closed. The README says “**Session history remains in the local SQLite database**” until the file is removed ([`README.md:117-124`](https://github.com/knarayanareddy/habitat-relay/blob/07f29808c43930d779029dc64e4beb7b471b85e1/README.md#L117-L124)). Tests confirm reset clears identity/delivery dedupe rows, not the whole event history ([`tests/store.test.js:101-107`](https://github.com/knarayanareddy/habitat-relay/blob/07f29808c43930d779029dc64e4beb7b471b85e1/tests/store.test.js#L101-L107)), while recap exports intentionally omit viewer IDs ([`tests/service.test.js:177-201`](https://github.com/knarayanareddy/habitat-relay/blob/07f29808c43930d779029dc64e4beb7b471b85e1/tests/service.test.js#L177-L201)). Impact: owner expectations for retention, backup, restore, and local-data disposal are still policy choices, not enforced operations. Recommended correction: define data lifetime, backup encryption, restore rehearsal, and key-loss handling before any real broadcaster use.

## 5. Production blockers and owner questions
Blockers:
1. No authenticated operator boundary for a shared/public deployment (HR-1).
2. No verified proxy/header trust model for CSRF, cookie security, and generated overlay URLs (HR-2).
3. No accepted retention/backup/restore/key-loss policy for SQLite state and encrypted Twitch credentials (HR-3).
4. No observed live Twitch OAuth callback, broadcaster authorization, EventSub delivery, or deployment identity at this SHA.

Owner questions:
- Will this remain local-only, or be hosted for remote control?
- Which host/proxy terminates TLS and owns `X-Forwarded-*` normalization?
- What backup/retention window is acceptable for the SQLite store?
- What is the procedure if `HABITAT_ENCRYPTION_KEY` is lost or rotated?
